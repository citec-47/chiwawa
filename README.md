# Little Paws — Chihuahua & Pomeranian Website

A responsive Next.js App Router site for public breed profiles, dog listings, and customer inquiries, with a PostgreSQL-backed administrator area. It does not accept payments.

## Requirements

- Node.js 20.9 or newer and npm
- PostgreSQL (Neon is supported) with a database URL
- Cloudinary account only if administrators need to upload new images

## Run locally

1. Install packages and create a private local environment file:

   ```sh
   npm install
   cp .env.example .env.local
   ```

   On PowerShell, use `Copy-Item .env.example .env.local`.

2. Set `DATABASE_URL`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD_HASH` in `.env.local`.
   Generate a bcrypt hash locally with:

   ```sh
   node -e "require('bcryptjs').hash('YOUR-UNIQUE-PASSWORD', 12).then(console.log)"
   ```

   Put the resulting hash in `ADMIN_PASSWORD_HASH`, enclosed in single quotes in `.env.local` so dotenv does not expand the bcrypt `$` characters. Do not reuse passwords or credentials shared in chat; rotate them before configuration. Never commit `.env.local`.

3. Apply the PostgreSQL schema and create starter content:

   ```sh
   npm run db:migrate
   npm run db:seed
   ```

   Seeding creates Chihuahua and Pomeranian breed profiles, two editable **draft** listings, and the administrator account. Drafts are not visible publicly until an owner reviews and publishes them. Their editable starter prices are $850 and $1,100 USD. No age, health, or availability claims are included.

4. Start the site:

   ```sh
   npm run dev
   ```

   Visit `http://localhost:3000`; administrator sign-in is at `/admin/login`.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | PostgreSQL connection string; use a rotated, private credential. |
| `ADMIN_EMAIL` | Initial administrator email, used by `npm run db:seed`. |
| `ADMIN_PASSWORD_HASH` | Bcrypt hash for the administrator password; never store the plain password. |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary cloud name, used by signed uploads. |
| `CLOUDINARY_API_KEY` | Cloudinary public API key. |
| `CLOUDINARY_API_SECRET` | Cloudinary signing secret; server-only, never expose to browser code. |

Breed and dog image uploads use a short-lived signed parameter set generated by an authenticated server route. Configure all three Cloudinary variables to enable uploads; the site works with the reviewed local photos without Cloudinary. Browser uploads are limited in the admin UI to JPG, PNG, or WebP files up to 6 MB. Visitors can select a published listing when sending an inquiry.

## Images and listing review

All 54 supplied photos are copied into `public/images/gallery/` and shown in the breed photo gallery: 34 Chihuahua photos from `cHIWA/` and 20 Pomeranian photos from `Pomerianian/`. Gallery photos illustrate the breeds and are not confirmed individual dog listings or availability. Starter dog records remain drafts and explicitly require owner review; publish only after verifying all details and image permissions. Confirm image permissions and review photos before production use.

Public breeder name, location, email, and phone are placeholders in the footer/contact section. Replace them with owner-approved public details before launch.

## Database and security

- SQL schema: `drizzle/0000_initial.sql`; typed Drizzle schema: `src/lib/db/schema.ts`.
- Admin sessions use random opaque tokens in HTTP-only, SameSite cookies; only SHA-256 token hashes and expiration timestamps are stored in PostgreSQL. Sessions expire after 12 hours.
- Admin routes and mutations require a valid session. Public visitors can read published listings and submit inquiries without an account.
- Request bodies are validated server-side; submitted display text is rendered through React escaping. Do not log inquiry contents or credentials.
- Use HTTPS in production, a least-privilege database role, rotated secrets, and appropriate database backups. This repository has not been deployed or connected to external services.
